# 01 · 需求分析（PRD）

> 项目暂定名：**半券 Hanken**（日语「半券」= 票根）
> 版本：v0.2 草案 · 2026-11 · 作者：ka1o
> v0.2 变更：识别改为「本地免费识别优先，大模型只做兜底」（§5.2、§7、§8、§10）

## 1. 背景与机会

### 1.1 问题

- 纸质票根（电影票、演唱会门票、火车票、登机牌）会**褪色、丢失、散落**在抽屉和钱包里。热敏纸票通常 1–3 年就看不清了。
- 电子票越来越多，但它们只存在于 App、邮件和截图里，**没有实体纪念感**，看完就被淹没在相册里。
- 当天拍的照片和票根是分开的，**回忆是碎片化的**。

### 1.2 竞品格局

| 产品                      | 定位         | 优点                | 不足（我们的机会）        |
| ------------------------- | ------------ | ------------------- | ------------------------- |
| Stubs (iOS)               | 演唱会记录   | OCR、地图、统计     | 偏演唱会；票面只是图片    |
| STUB (iOS)                | 全品类票根   | 本地加密、日历视图  | 视觉朴素，无仿真          |
| Turnstile                 | 社交型剪贴簿 | 动态、往年今日      | 偏社交，日本 / 中文市场弱 |
| TicketShelf / 票根儿      | 国内全品类   | AI 识票、评分、周边 | 卡片式 UI，无物理质感     |
| 时光票根 / Tokii / FlyTix | 模板生成票根 | 模板好看、导出 PNG  | 静态模板，无真实材质      |

**结论**：「扫描 → 识别 → 时间线 → 加照片」已经是**基本功能**，大家都在做。**几乎没有人把票做得像真的一样**：有材质、有光泽、能撕能翻。这就是半券的切入点。

### 1.3 产品定位

> **把每一张票，变回一张"真的票"。**
> 一个能扫描、整理、珍藏票根的个人纪念册。每张票都有真实的纸张、烫金和检票痕迹，并且能和当天的照片放在一起。

### 1.4 目标

| 类型   | 目标                                                     |
| ------ | -------------------------------------------------------- |
| 作品集 | 体现创意开发（WebGL/Shader）、AI、移动端、完整产品化能力 |
| 用户   | 上线 6 个月：注册 5,000 人，月活 1,500，30 天留存 ≥ 25%  |
| 收入   | 上线 6 个月：Pro 付费转化 ≥ 3%，开始卖出实体周边         |
| 传播   | 带动效的分享视频在小红书 / Instagram / X 上自然传播      |

## 4. 用户故事

### 4.1 录入

- **US-01** 作为用户，我想用手机拍下纸质票，App 自动识别票的边缘并把它拉正。
- **US-02** 作为用户，我想从相册导入电子票截图或照片。
- **US-03** 作为用户，我希望 App 自动识别日期、名称、地点、座位，我只需要确认。
- **US-04** 作为用户，识别出错时我能快速修改；没有票的时候也能手动创建。
- **US-05** 作为用户，我想一次扫描多张票（连拍）。
- **US-06** 作为用户，没有网络或者 AI 次数用完时，App 也能自动识别出基本信息，不用全部手动填。

### 4.2 浏览

- **US-10** 作为用户，我想按时间顺序看到所有的票，像翻一本票夹。
- **US-11** 作为用户，我想按类型、年份、城市、标签筛选。
- **US-12** 作为用户，我想搜索演出名、艺人、地点。

### 4.3 单张票

- **US-20** 作为用户，打开一张票时，它看起来像真的：有纸张质感，倾斜手机时会反光。
- **US-21** 作为用户，我能翻到票的背面，查看备注和信息。
- **US-22** 作为用户，我能给这张票上传当天的照片和视频，并按顺序排列。
- **US-23** 作为用户，我能写下当天的感受，记录同行人，并打分。
- **US-24** 作为用户，我能「撕下副券」或「检票打孔」，留下仿真痕迹。

### 4.4 分享与回顾

- **US-30** 作为用户，我想把一张票导出成图片或短视频，发到社交平台。
- **US-31** 作为用户，我想在年底看到「年度票根」回顾。
- **US-32** 作为用户，我想在地图上看到我去过的场馆和城市。
- **US-33** 作为用户，我想收到「一年前的今天」提醒。

### 4.5 账号与数据

- **US-40** 作为用户，不注册也能使用（数据保存在本机）。
- **US-41** 作为用户，登录后能在多台设备之间同步。
- **US-42** 作为用户，我能导出全部数据，也能删除账号。

| ------- | ------------------------------------------ | ------ |
| SCAN-01 | 相机取景，实时检测票据边缘，自动或手动拍摄 | P0     |

### 5.2 识别（OCR）

> **原则：能在手机上免费识别的，就不花钱调用大模型。** 识别分三级，前一级不够用才进入下一级：
> 1. **本地识别（免费）**：条码解析 + 手机系统自带的文字识别 + 规则提取字段。
> 2. **云端文字模式（便宜）**：只把本地识别出的**文字**发给大模型整理成字段，不上传图片。
> 3. **云端图片模式（最贵）**：本地连文字都认不清时（花体字、镭射反光、Web 端），才上传压缩图给多模态大模型。

| ID     | 需求                                                                                                                              | 优先级                                      |
| ------ | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| OCR-01 | 识别票据类型（机票 / 火车 / 电影 / 演唱会 / 话剧 / 体育 / 展览 / 其他）：先用本地关键词规则判断，判断不了再交给大模型             | P0                                          |
| OCR-02 | 提取字段：标题、日期时间、时区、场馆、城市、座位、价格；交通票还要提取出发地、目的地、班次、航司或铁路公司                        | P0                                          |
| OCR-03 | 支持中文、日文、英文、韩文票面                                                                                                    | P0                                          |
| OCR-04 | 每个字段带置信度，置信度低的高亮提示用户确认                                                                                      | P0                                          |
| OCR-05 | 登机牌条码（IATA BCBP）在本地解析，**不上传**                                                                                     | P0                                          |
| OCR-06 | 根据场馆名补全经纬度（地理编码）                                                                                                  | P1                                          |
| OCR-07 | 根据演出名补全海报、艺人信息                                                                                                      | P2                                          |
| OCR-08 | **本地文字识别**：iOS 使用系统自带的 Apple Vision，Android 使用 Google ML Kit，离线可用、不收费                                   | P0                                          |
| OCR-09 | **规则提取**：从本地识别出的文字里提取日期、时间、座位、价格、车站等字段；固定版式的票（JR 车票、登机牌、主要连锁影院）有专用规则 | P0（通用规则 + JR + 登机牌） / P1（影院等） |
| OCR-10 | **云端兜底**：标题或日期缺失、置信度低时，自动调用大模型；**优先用文字模式**，文字质量太差时才用图片模式                          | P0                                          |
| OCR-11 | 离线或 AI 次数用完时，先显示本地识别结果让用户确认或修改；联网后用户可以选择「用 AI 再识别一次」                                  | P0                                          |
| OCR-12 | 记录用户对识别结果的修改（只记录字段名和规则命中情况，不记录票面内容），用于改进规则和提示词                                      | P1                                          |

## 6. 票型与字段

**通用字段**：类型、标题、副标题、活动时间（含时区）、结束时间、场馆、地址、城市、国家、经纬度、座位、价格 + 币种、备注、评分、标签、同行人。

| 票型                       | 扩展字段                                                                  | 默认材质 / 模板                    |
| -------------------------- | ------------------------------------------------------------------------- | ---------------------------------- |
| ✈️ 机票 `flight`           | 航司、航班号、出发和到达机场（IATA 三字码）、登机口、舱位、登机时间、座位 | 登机牌（硬卡纸 + 副券打孔线）      |
| 🚄 火车 `train`            | 铁路公司、车次、出发站和到达站、车厢、座位、席别                          | 日本磁气券 / 中国高铁票 / 通用车票 |
| 🎬 电影 `movie`            | 影院、影厅、片名、场次、版本（IMAX、4DX 等）                              | 热敏纸                             |
| 🎤 演唱会 `concert`        | 艺人、巡演名、场次、区域 / 排 / 号、入场序号                              | 镭射烫金硬卡                       |
| 🎭 话剧 / 音乐剧 `theater` | 剧名、剧团、楼层 / 排 / 号                                                | 硬卡纸                             |
| ⚽ 体育 `sports`           | 主队、客队、赛事、看台                                                    | 硬卡纸                             |
| 🖼 展览 `exhibition`        | 展名、美术馆、有效期                                                      | 普通纸                             |
| 🎟 其他 `other`             | 自定义                                                                    | 普通纸                             |

## 7. 非功能需求

| 类别         | 指标                                                                                                                                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **性能**     | 详情页渲染：iPhone 12 / 同级别 Android 达到 60fps，低端机不低于 30fps，否则自动降级；时间线滚动 60fps；首屏 LCP < 2.5s（4G）；首屏 JS < 250KB（gzip），three.js 按需懒加载   |
| **识别**     | 本地识别 p95 < 1.5 秒；需要云端兜底时整体 p95 < 6 秒；关键字段（标题、日期）最终准确率 ≥ 90%；**本地识别完成率**（不需要调用大模型的比例）MVP 阶段 ≥ 50%，v1.0 ≥ 70%         |
| **离线**     | 浏览、编辑、新建（手动录入）离线都能用；原生 App 离线也能本地识别；联网后再同步，需要的话再用 AI 补充识别                                                                    |
| **隐私**     | 扫描图和照片默认私有；分享时二维码、条码打码；登机牌条码只在本地解析；**本地能识别的票不向任何 AI 服务发送数据**；需要云端兜底时优先只发文字；发给大模型的数据不用于模型训练 |
| **安全**     | 数据库开启行级安全（RLS），用户只能访问自己的数据；存储用签名 URL 访问，并设置过期时间                                                                                       |
| **可访问性** | 遵循系统的「减弱动态效果」设置；颜色对比度达到 WCAG AA；支持 VoiceOver 读出票面信息                                                                                          |
| **国际化**   | 中文、日文、英文；日期、币种按地区格式显示；所有时间都保存时区                                                                                                               |
| **兼容性**   | iOS 16+、Android 10+；浏览器：Safari 16+、Chrome 110+                                                                                                                        |
| **可靠性**   | 原图永不覆盖；所有编辑可以撤销；云端每天备份                                                                                                                                 |

| 方案                                  | 免费版          | Pro（参考价：日本区 JPY 300/月 或 JPY 2,400/年；其他地区按当地价格） |
| ------------------------------------- | --------------- | -------------------------------------------------------------------- |

## 9. 关键指标

| 环节 | 指标                                                             |
| ---- | ---------------------------------------------------------------- |
| 激活 | 新用户 24 小时内录入第 1 张票的比例 ≥ 60%                        |
| 核心 | 平均每个月活用户每月新增票数；附加照片的票占比                   |
| 传播 | 分享导出次数 / 月活；通过分享带来的新用户占比                    |
| 留存 | 第 1 / 7 / 30 天留存                                             |
| 收入 | 付费转化率、每用户平均收入（ARPU）、周边订单数                   |
| 质量 | 识别后被用户修改的字段比例、本地识别完成率、渲染降级比例、崩溃率 |
| 成本 | 平均每张票的 AI 费用；文字模式和图片模式的调用比例               |

## 10. 风险与对策

| 风险                                           | 影响                 | 对策                                                                                                                   |
| ---------------------------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 市场上已有不少同类 App                         | 用户获取难           | 把仿真效果做到极致，并且靠分享视频传播；首发主攻日本和中文市场                                                         |
| WebGL 在低端机上卡顿                           | 体验差               | 列表只用缩略图；整个 App 只用一个 WebGL Canvas；自动降级                                                               |
| AI 识别成本                                    | 亏钱                 | 本地识别优先，大部分票不花钱；兜底时优先用文字模式；免费版限次数；按票型统计本地完成率，优先给调用 AI 最多的票型补规则 |
| 本地识别准确率不够（花体字、镭射反光、Web 端） | 用户要手动改很多字段 | 用 AI 兜底；用评测集分别衡量本地和云端的准确率；根据用户修改记录持续补规则                                             |
| 识别不准                                       | 用户流失             | 必须经过用户确认；置信度低的字段高亮；记录用户的修改，用来优化提示词                                                   |
| 隐私（票面有姓名、订单号）                     | 法律和信任问题       | 分享时打码；条码本地解析；在隐私政策中明确说明                                                                         |
| 一个人开发，范围失控                           | 延期                 | 严格按 M0 → MVP → v1 推进，每个阶段都有可以演示的成果                                                                  |
| 商标、版权（艺人海报等）                       | 下架风险             | MVP 不自动抓取海报；用户上传的内容由用户自己负责                                                                       |
